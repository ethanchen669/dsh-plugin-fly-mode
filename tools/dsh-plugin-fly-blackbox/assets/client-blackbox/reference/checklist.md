# 客户端黑盒排查 · 全流程检查清单

> 配套：`playbook.md`（五阶段全文）· `case-ttw.md`（脱敏案例）· `rules.schema.md`（规则 schema）
>
> 用法：复制一份，边做边勾。**每个 Gate 没过，不要进入下一阶段。**

---

## Phase 0 · 症状分流

- [ ] 用 S1/S2/S3/G 模型写出问题陈述
      `S1 显示___ ｜ S2 提交___ ｜ S3 存储___ ｜ 闸门在〈前端 / 服务端〉`
- [ ] 把用户已尝试的无效操作逐条列出，并解释**为什么无效**
- [ ] 找出提示语原文，去响应体里搜（T2）
      - [ ] 搜到 → 服务端判定
      - [ ] 搜不到 → 纯前端文案
- [ ] 明确"用户物理上做不到的那个动作"是什么（例：页面没有编辑控件）

**Gate 0**：能自洽解释"为什么重登 / 重装 / 换设备全部无效"。

## Phase 1 · 建立可观测性

### 环境探测
- [ ] 用 `bx_doctor` 的第④段扫一遍：本机有没有别的代理工具在监听常见高位端口
      （Clash / Surge / mihomo 之类；它们可能抢流量或与我们的代理冲突）
- [ ] 确认当前**系统代理真实状态**（`bx_sysproxy status`；看 `Enabled` 而不是 `Server` 字段）
- [ ] 代理证书目录设到工作区内（`.fly-blackbox/mitmproxy`），别用默认的 `~/.mitmproxy`
- [ ] 装 mitmproxy：**注意解释器**。系统自带 / 常见 `pip3` 可能装到老版本，
      dump 格式与新版不同（读取器会按版本闸拒绝）。用显式版本的解释器建 venv，
      并对齐版本：
      - [ ] `bx_proxy status` 会告诉你本机缺不缺 mitmdump，以及点名解释器的两行安装命令
      - [ ] 若镜像拉不到包，直接换官方源：`-i https://pypi.org/simple`
- [ ] 信任 CA（macOS 要写系统钥匙串，需要密码 → **人的动作**）
      - [ ] 命令用 `bx_ca command` 取；本仓**永不提权**
      - [ ] 事后用 `bx_ca verify` 取证据（退出码 + 指纹）
- [ ] 系统代理 HTTP 与 HTTPS **两个都要设**（`bx_sysproxy on`）
- [ ] **写好还原命令**：`bx_sysproxy status` 每次都会回显一条

### 自检三连（Gate 1 硬指标）
- [ ] ① HTTP 通过代理返回 200
- [ ] ② HTTPS 通过代理且 `--cacert` 用 confdir 里那张 CA，返回 200
- [ ] ③ **HTTPS 证书链的签发者就是 confdir 里的 mitm CA**（只看 200 不算过）
- [ ] ④ 打开目标客户端，日志出现 `[NEW HOST]`
- [ ] 若 ③ / ④ 失败：区分"自带网络栈忽略代理" vs **证书绑定**（pinning）→ 后者跳 Phase 4 人工分支

**Gate 1**：①②③④ 全绿。（`bx_doctor` 把这几条一次判完；它说"无抓包能力"时是**一等状态**，不是失败。）

## Phase 2 · 协议测绘

- [ ] 把目标功能**正常路径 + 出错路径各点一遍**（保持代理开着）
- [ ] `bx_flows hosts`：输出域名分布，标出业务 API 域名 vs 静态资源 CDN
- [ ] `bx_flows list`：逐条记录接口：`method / path / 关键参数 / 鉴权方式 / 响应模型`
- [ ] 标注：只读接口 / 写入接口 / **预检接口**（`check` / `verify` / `pre`）
- [ ] 提示语原文全局搜索（`bx_flows grep --pattern '…'`），定位到具体接口与字段（T2）
- [ ] 拉一条**对照组指纹**：必然存在的路径 + 必然不存在的路径，各返回什么

**Gate 2**：能画出"操作 → 请求 → 谁判断"的流程图。

## Phase 3 · 三源对账 + 诱出

### 对账
- [ ] S1 vs S3：界面显示值 vs 读接口返回值 → 差值 = 渲染兜底（T1）
- [ ] S2 vs S3：抓到的请求体 vs 读接口返回值 → 差值 = 服务端丢弃
- [ ] **变更审计**（`bx_diff`）：对整条记录做**改前 / 改后 diff**，列出所有真正变化的字段
- [ ] 看记录里的"最后修改时间"字段有没有变（判断接口到底有没有被执行）
- [ ] 注意 diff 的三种标注：**缺失** / **假值** / **类型变化** —— 它们指向完全不同的根因

### 诱出法（仅当请求根本没发出）
- [ ] 选定**单一变量**：注入哪个字段、注入成什么值
- [ ] 注入值考虑 T5：枚举字段优先试**字符串 `"0"`**（JS 真值，能同时过判假与判空）
- [ ] 明确定义"观察点"（界面显示 / 是否发包 / 响应码）
- [ ] 规则写进 `rules.json`（schema 见 `rules.schema.md`），改完**保存即生效，不重启**
- [ ] 注入后复现操作，确认请求**确实发出**
- [ ] 抓下完整请求体（接口名、字段、编码一次全拿到）
- [ ] **立即撤掉注入**（显式 `{"enabled": false}` —— 空文件不算关），避免污染后续判断

### 找写入路径（非破坏性）
- [ ] 对候选路径发 `GET`
      - [ ] `404` → 不存在
      - [ ] `405 / not supported` → **存在，只接受 POST** ← 目标
      - [ ] `200` → 可读
- [ ] 记录候选接口清单（后续交给厂商）

**Gate 3**：能用一句话说清"哪个接口 / 哪个字段 / 在哪一层丢的"。

## Phase 4 · 修复决策

- [ ] 目标字段能否写入存储？
      - [ ] 有专用写接口 → 直接调用（诱出法拿格式）
      - [ ] 有通用接口但不落该字段 → 白名单缺失 → **厂商修**
      - [ ] 无写接口 → 判断闸门性质
- [ ] 闸门性质（T6）
      - [ ] 客户端门禁（服务端交出了 `state` / `confirm` / `Y` / `N` 决策权）→ 可篡改响应解除
      - [ ] 服务端门禁（直接拒绝）→ **停手**，转人工 / 工单 / 换入口

### 写入前风险清单（逐条勾选，任一不明确就不要写）
- [ ] 该接口是**选择性更新**还是**整行覆盖**？
- [ ] 请求体里有没有**打码字段**（手机号 / 身份证是星号）？整行覆盖会把真实值写成星号
- [ ] 接口名是否含 `save` / `insert` / `create`（可能是插入，产生重复记录）？
- [ ] 改动可回滚吗？有软删除吗？
- [ ] 绕的是"展示 / 自检"还是"计费 / 资格 / 身份"？**后者一律不碰**

**Gate 4**：用户目标达成，且**无脏数据**（或已记录并规划回滚）。

## Phase 5 · 收口

- [ ] **先关系统代理**（`bx_sysproxy off`），**再停代理进程**（`bx_proxy stop`）（顺序！）
- [ ] 验证网络恢复正常
- [ ] 存档全量流量（`.mitm`）、分析结论、变更 diff、精确时间线
- [ ] 存档前**脱敏**（token / 手机号 / 身份证）
- [ ] 写工单，七段齐全：上下文 / 现象 / **已排除项** / 证据(diff) / 定位 / 可执行诉求 / 安全披露
- [ ] 安全发现：**只披露，不利用**
- [ ] 留一份"下次怎么再做一遍"的操作手册（若是需要重复执行的绕过）

---

## 通用纪律（全程）

- [ ] 一次只改一个变量，并写明观察点
- [ ] 每个结论都要有**独立的验证手段**（不靠接口回显）
- [ ] 在证明管道通畅之前，不对"没抓到数据"做任何解释
- [ ] 每次操作前问一句：**这一步可逆吗？**
- [ ] 只碰自己的账号，只碰自己的数据
